# TradeLog 요구사항 정의서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 프로젝트 | TradeLog |
| 상태 | Draft |
| 작성자 | 홍길동 |
| 마지막 수정 | YYYY-MM-DD |
| 버전 | 0.1 |

## 프로젝트 목적

사용자가 자신의 주식 매매 기록을 저장하고,
매매 이유와 결과를 복기할 수 있는 웹 애플리케이션을 제공한다.

## 기능 요구사항

| ID | 기능 | 요구사항 | 우선순위 | 완료 조건 |
|---|---|---|---|---|
| FR-001 | 회원가입 | 사용자는 아이디, 비밀번호, 닉네임으로 가입할 수 있다. | Must | 정상 정보 입력 시 회원이 DB에 저장된다. |
| FR-002 | 아이디 중복 확인 | 중복된 LOGIN_ID로 가입할 수 없다. | Must | 기존 아이디 입력 시 가입이 거부된다. |
| FR-003 | 로그인 | 등록된 회원은 로그인할 수 있다. | Must | 정상 로그인 시 세션에 회원 정보가 저장된다. |
| FR-004 | 매매 등록 | 로그인 사용자는 매매일지를 등록할 수 있다. | Must | 입력 데이터가 TRADE 테이블에 저장된다. |
| FR-005 | 목록 조회 | 자신의 매매일지를 목록으로 확인할 수 있다. | Must | 본인의 거래만 조회된다. |
| FR-006 | 상세 조회 | 특정 매매일지의 상세 내용을 확인할 수 있다. | Must | 선택한 거래의 상세 정보가 표시된다. |
| FR-007 | 수정 | 자신의 매매일지를 수정할 수 있다. | Must | 수정한 내용이 DB에 반영된다. |
| FR-008 | 삭제 | 자신의 매매일지를 삭제할 수 있다. | Must | 삭제 후 목록에서 해당 거래가 제거된다. |
| FR-009 | 대시보드 | 거래 요약 정보를 확인할 수 있다. | Should | 거래 횟수와 최근 거래 등이 표시된다. |

## 비기능 요구사항

| ID | 항목 | 요구사항 |
|---|---|---|
| NFR-001 | 보안 | 비로그인 사용자는 개인 매매정보에 접근할 수 없다. |
| NFR-002 | 데이터 무결성 | LOGIN_ID 중복 저장을 허용하지 않는다. |
| NFR-003 | 유지보수 | Controller / Service / Mapper의 역할을 분리한다. |
| NFR-004 | 사용성 | 입력 오류 발생 시 사용자에게 원인을 표시한다. |

## 제외 범위

첫 MVP에는 다음 기능을 포함하지 않는다.

- 실시간 증권 시세 연동
- 증권사 API 연동
- 자동 매매
- 소셜 로그인
- 모바일 앱
